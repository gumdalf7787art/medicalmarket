메디컬마켓 저장소 루트의 [팀원 업무 지침](../../../docs/product-guide-editorial.md)을 읽고 요청받은 장비와 작업 범위를 확인한다.

1. 제품 검색 API로 후보를 찾고 상세 응답의 id, 공식명, 모델, 대표 사진, 갤러리, 상세 설명 이미지(guidePhotos.details)를 확인한다. 동명이거나 규격이 다른 제품은 모델·제조사까지 대조한다.
2. 제품과 주제로 기존 안내 글을 조회한다. 개정 요청이면 기존 주소와 revision을 유지하고, 별도 질문을 다루는 신규 글이면 고유 주소를 정한다.
3. 제품과 독자의 질문에 맞춰 제목·요약·본문·사진 순서를 작성한다. 중복을 제외한 제품 이미지 2~4장을 선택하고, 상세 설명에서는 글에 필요한 영역만 잘라 별도 이미지로 만들고, 같은 제품의 갤러리에 등록한 뒤 사용한다. 상세 설명 원본 전체는 삽입하지 않는다. 확인한 근거와 미확인 사항은 원고 밖의 작업 보고에 남긴다.
4. 원고나 기획 요청은 해당 산출물을 전달한다. 저장·발행 요청이면 [API 계약](../../../docs/product-guide-api.md)에 따라 전용 토큰으로 API를 호출하고 응답과 저장 상태까지 확인한다. 토큰이 연결되지 않았으면 저장·발행이 보류된 이유를 보고한다. 이미 공개된 글의 수정안을 요청받았을 때 원고를 보관하려고 published=false로 덮어쓰면 기존 글이 비공개가 되므로 수정안만 전달한다.
5. 공개 발행 후 로그인 없는 글 주소, 모델명 검색, 해당 제품의 견적 요청 링크를 확인한다. 완료 보고에 제품 ID, 글 제목, 저장 상태, 확인 결과를 적는다. API 호출이 실패했으면 작성 완료와 발행 완료를 구분한다.

## 채팅에서 직접 발행

1. 공개 요청이면 메디컬마켓 발행 도구의 `guide_status`를 호출한다. `connected: true`와 `state: active`를 확인하고 진행한다. 403이면 실패한 조회 단계와 확인 가능한 오류를 기록한다. 오류 코드만으로 승인 해제를 단정하지 않는다.
2. 요청한 편수만큼 공개 제품과 고유 주제를 고르고 위 편집 절차에 따라 작성한다. 제공된 원고가 있으면 해당 원고의 제품 ID와 기존 글 주소를 대조한다.
3. 글마다 `publish_guide`에 `productId, slug, revision, title, summary, body, images`를 전달한다. 새 글은 `revision: 0`을 사용한다. 이미 공개된 글은 미발행분 처리에서 제외하고, 수정 요청일 때만 최신 버전에 맞춰 갱신한다.
4. 글마다 도구가 반환한 `published: true`, 버전, 공개 URL을 확인한다. 이 도구는 로그인 없는 상세 페이지, 검색 결과, 선택 사진과 제품 링크를 검증한다. 저장 후 검증 오류나 응답 중단이 발생하면 같은 주소의 상태부터 조회하고 미완료분만 처리한다. 최종 보고에는 글 제목과 확인된 공개 링크를 담는다.
